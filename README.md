# Photo studio bot

Telegram-бот, который делает фотосессии с лицом пользователя по шаблонам из
Obsidian. Каталог правится в веб-админке, бот крутится в том же процессе.

## Запуск

```
pip install -r requirements.txt
```

Дальше `run.bat` (или `python -m app.main`). Админка — <http://127.0.0.1:8766>.
При первом запуске пустая база сама подтягивает шаблоны из хранилища.

## Как это устроено

Один процесс на всё: правка промпта в браузере видна боту сразу — админка пишет
в базу и сбрасывает кеш каталога, следующая генерация идёт уже по новому тексту.

| Файл | Что делает |
| --- | --- |
| `app/main.py` | точка входа: админка + бот |
| `admin/server.py` | FastAPI: каталог, редактор шаблона, настройки |
| `bot/config.py` | пути, порт, ключи из `.env` |
| `bot/db.py` | SQLite: шаблоны, настройки, юзеры, лица, задачи, платежи |
| `bot/prompt.py` | набор полей шаблона и сборка их в прозу для модели |
| `bot/store.py` | кеш каталога для рантайма + инвалидация при правке |
| `bot/gemini.py` | текстовый клиент kie Gemini (только для офлайн-инструментов) |
| `tools/import_vault.py` | импорт шаблонов из Obsidian |
| `tools/structure.py` | разбор свободного текста по полям |

## Как устроен шаблон

У каждого шаблона один и тот же набор полей: `shot`, `subject`, `wardrobe`,
`styling`, `location`, `pose`, `lighting`, `camera`, `extras`, `negative`.
Поэтому новый шаблон — это форма, а не сочинение, а вариации делаются подменой
одного поля.

Модели при этом уходит **проза**, собранная из полей: гайд Google по
nano-banana просит описанную сцену, а не список ключей. Обе формы лежат рядом,
и переключатель в настройках позволяет сравнить их на реальных генерациях.

`subject` намеренно не описывает лицо — ни цвет глаз, ни тон кожи, ни цвет
волос: всё это приходит с фото пользователя, и текстовое описание с ним
конфликтует. Форма причёски и макияж живут в `styling`, цвет — нигде.

## Импорт из Obsidian

```
python -m tools.import_vault      # свободный текст из хранилища
python -m tools.structure         # разложить его по полям
python -m tools.structure --all   # переразобрать все, а не только новые
```

Импорт берёт `BOYS/` и `GIRLS/` из `VAULT_DIR`: имя файла — название, тело —
промпт, `![[...]]` — превью (жмётся в webp и кладётся в `assets/previews/`).

Импорт идемпотентный: гоняй сколько угодно, двигаются только изменившиеся
шаблоны. Промпт, который ты правил в админке, **не перетирается** — новый текст
из хранилища ложится рядом, шаблон помечается «vault moved», и в редакторе
появляется кнопка «Use vault text».

Каждый шаблон в хранилище просил лицо по-своему («use 100% upload face»,
«Face alignment: 100% accurate to reference», `[my photo]`). Импорт вырезает
такие вставки — за лицо отвечает одна общая инструкция в настройках. Там, где
вырезание сломало бы фразу, подставляется нейтральное «the person».

`tools.structure` прогоняет текст через Gemini (kie) и одним проходом делает
две вещи: раскладывает по полям и чинит опечатки распознавания вроде
«stylishblack», «scaffolding sky» и «behind Thema on the wall». Требует
`KIE_API_KEY`. Сырой текст остаётся на строке, так что неудачный разбор всегда
можно переделать — кнопкой в редакторе или `--all`.

## Ограничения

Админка слушает только `127.0.0.1` и **не имеет авторизации**. Через неё видны
платежи и загруженные лица пользователей — прежде чем выкладывать на сервер,
нужен вход по паролю.
